# Chion RUAD → V3 交接文档

写给下一个接手的 AI。v2 决定重开成 v3。不要复用 v2 的代码（问题太多），从零写。
本文只讲两件事：**这个应用要干什么**，和**唯一必须照抄的一个关键教训（双语配对安全）**。

---

## 1. 这个应用是什么

日语轻小说阅读器，面向"边读边学"。三条核心动作：

1. **点词 → 写剪贴板**，联动外部 GoldenDict 弹词典（应用本身不含词典 UI，只往剪贴板写词的原形）。
2. **选中文本 → 流式 AI 分析**（OpenAI 兼容接口，讲解语法/翻译）。
3. **朗读**（TTS，本地 GPT-SoVITS 或在线），带情感分类选语气。

支持**中日双语 EPUB**（一段日文一段中文，按 `t` 显示对应中文译文）。

技术栈参考：Electron + React + TypeScript + Vite。日语分词用 Sudachi（WASM）。

---

## 2. 最重要的教训：中日双语配对安全

这是 v2 反复踩坑、最终才做对的地方。v3 务必照抄这套判断逻辑，否则会出灾难性 bug。

### EPUB 的真实结构

以参考书 `楽園ノイズ.epub` 为例，双语 EPUB 的真实排版是：

```html
<p class="calibre" style="opacity:0.4;">日文原文…<ruby>魔<rt>ま</rt></ruby>…</p>   ← 日文（被调暗）
<p>中文译文…</p>                                                              ← 中文（裸 <p>）
<p class="calibre"><br class="calibre1" /></p>                                ← 空段（间隔）
<p class="calibre" style="opacity:0.4;">下一段日文…</p>
<p>下一段中文…</p>
```

规律：
- **日文原文段**带 `style="opacity:0.4;"`（阅读软件把原文调暗），常含 `<ruby>` 注音。
- **中文译文段**是裸 `<p>`，全亮。
- 严格 **1:1 交替**，中间可能夹 `<p><br></p>` 空段。

### 判断规则（照抄）

1. **优先用 `opacity < 1` 作为"这是日文原文"的权威标记**（确定性，最可靠）。
2. **没有 opacity 标记时，回退：只要段落含假名，就判日文。** 纯汉字无假名才判中文。
3. **配对**：一个日文段 + 其后第一个非空段（若是中文）→ 配成一对。跳过中间的空段。
4. 中文段默认隐藏，按 `t` 显示当前段对应的中文。

### 绝对不能犯的错误（v2 的灾难）

- ❌ **不要用"假名比例"猜语言**（比如"假名 < 15% 判中文"）。日文里有很多汉字多、假名少的句子（如「吾輩は猫である」），会被误判成中文**而隐藏掉** —— 用户在读日语小说，日文被藏起来是灾难。
- ✅ **安全方向永远是"宁可多显示中文，绝不隐藏日文"。** 有假名的段落，无论如何都当日文显示，绝不隐藏。

### v3 更好的做法

**在导入 EPUB 时就把日/中配对成结构化数据存库**（每段日文 ↔ 对应中文），而不是每次渲染时临时推导。阅读器只在日文上做操作（分词、注音、AI、朗读），中文作为译文附属、按需显示。这样配对只算一次，也更稳。

---

## 3. 一句话性能提醒

v2 最大的痛点是**整章一次性分词 + 一次性渲染上万节点**，每翻新章卡几秒。
v3 从第一天就要为此设计：**视口懒加载**（只分词看得到的段落）+ **后台预取**（读当前章时预分词下一章）。别一次性塞整章。
